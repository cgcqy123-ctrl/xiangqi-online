# 中国象棋 · 联机版（纯静态 / GitHub Pages 可托管）

一个**不需要服务器、不需要注册账号**的双人中国象棋网页：房主点一下「创建房间」拿到 4 位房号，
把房号发给朋友，他输入房号就能入座开局；第三个人起自动变成观战。

联机走 WebRTC 点对点直连（PeerJS），对局逻辑完全在房主浏览器里跑，另一方只发动作、收视图。
整个网站就是几个静态文件，直接丢到 GitHub Pages 就能玩。

## 三分钟部署到 GitHub Pages

仓库已经准备好了（`git` 已初始化并提交、`.github/workflows/pages.yml` 自动部署、`.nojekyll` 已加）。

**1. 在 GitHub 上新建一个空仓库**（例如 `xiangqi-online`），不要勾选 README / .gitignore。

**2. 推送代码**（把地址换成你自己的）：

```bash
git remote add origin https://github.com/<你的用户名>/xiangqi-online.git
git branch -M main
git push -u origin main
```

**3. 打开仓库 → Settings → Pages → Build and deployment**
- **Source 选 `GitHub Actions`**（推荐，本仓库自带工作流，推送后自动发布）；
- 或者选 `Deploy from a branch` → `main` / `/ (root)`（仓库根目录就是网站根目录）。

**4. 等 1 分钟左右**，访问：

```
https://<你的用户名>.github.io/xiangqi-online/
```

把链接发到群里就能开局了。手机浏览器建议加「添加到主屏幕」，和 App 差不多。

> 免费账号的 Pages 只对 **public 仓库**开放；私有仓库要用 Pro。
> 自定义域名：Settings → Pages → Custom domain 填域名，再在域名服务商加一条 CNAME。

## 本地试玩

浏览器的 WebRTC 只在**安全上下文**（`https://` 或 `http://localhost`）下可用，
所以**不能直接双击 `index.html`**（`file://` 会失败），必须起一个本地服务器：

```bash
node tools/serve.mjs          # 自带零依赖静态服务器，默认 http://localhost:8080
# 或者
python -m http.server 8080    # 或者 npx serve .
```

然后开**两个浏览器标签页**（或一个电脑 + 一部手机连同一 WiFi）分别创建 / 加入同一个房号；
想试观战就再开第三个标签页输同一个房号。一个人也能「两个标签页对打」。

## 怎么玩

| 步骤 | 说明 |
| --- | --- |
| 建房 | 填昵称 → 「创建房间」→ 屏幕上的 4 位房号就是房间号，房主执红先行 |
| 加入 | 填昵称 + 4 位房号 → 「加入房间」，自动坐在空位上（第二位执黑） |
| 开局 | 两人到齐后房主点「开始对局」 |
| 走子 | 点自己的棋子 → 棋盘上出现绿色小圆点（可走点）和红圈（可吃子），点目标格即落子；点不动的子会告诉你原因（被自家子堵住 / 一动就被将军） |
| 视角 | 红方看到红子在下，**黑方自动把棋盘转 180°**，自己的子永远在下方（楚河汉界也跟着换边） |
| 将军 | 对方被将军时棋盘顶部会闪「将军！」，被将的老将同时高亮 |
| 悔棋 | 点「悔棋」→ 对方同意后回到**你上一步之前**：刚走完就被同意只退 1 手，对方已经应招则退 2 手 |
| 求和 | 点「求和」，对方同意即和棋；对方拒绝则继续 |
| 认输 | 点「认输」需要再点一次「确定认输」，防误触 |
| 结束 | 将死 / 困毙 / 认输 / 双方和棋都会弹出结算浮层，房主可点「再来一局」 |
| 观战 | 第三位起自动进入观战位（最多 6 人），只能看棋和聊天 |
| 聊天 | 右侧（手机上在下方）切到「聊天」页，有几句快捷语，也能自己输入 |

棋谱会实时记录成中文记谱（`炮二平五`、`马8进7`、`前兵进一`……），点开就能复盘聊天记录里的每一手。

## 已实现的规则

标准中国象棋，红先黑后，**没有暗棋，双方看到的是同一个棋盘**。

| 棋子 | 走法 |
| --- | --- |
| 帅 / 将 | 九宫内直走一步；两将同列且中间无子时视为互相攻击（白脸将），不允许走成照面 |
| 仕 / 士 | 九宫内斜走一步 |
| 相 / 象 | 走「田」，塞象眼不能走，不能过河 |
| 马 | 走「日」，蹩马腿不能走 |
| 车 | 直线任意步，遇子即止 |
| 炮 | 直线任意步，吃子必须隔一个炮架（打不到中间没有炮架的目标） |
| 兵 / 卒 | 向前一步；过河后可以左右横走，不能后退 |

判定：

- **将死**：轮到的一方被将军且没有任何合法走法 → 判负。
- **困毙**：轮到的一方没被将军但一步也走不了 → 同样判负（中国象棋规则）。
- **不得送将**：任何让自己被将军（含走成两将照面）的走法都不合法，界面直接不给落点。
- 悔棋 / 求和 / 认输 / 再来一局，都是「需要对方同意」或「只有房主能开新局」的社交规则。
- **不做**长将判负、长捉判负、60 回合无吃子和棋这些循环局面判罚——出现循环时由双方自行约定（见「已知限制」）。

## 联机原理

```
房主浏览器 ──(WebRTC DataChannel)──> 对手（黑方）
     ├──────(WebRTC DataChannel)──> 观众 A
     └──────(WebRTC DataChannel)──> 观众 B
            ↑ 只靠公共 PeerJS 信令服务器牵线（不传对局数据）
```

- **信令**：用 PeerJS 官方免费公共服务器（`0.peerjs.com`）交换 SDP，只负责「牵线」，不参与游戏。
- **对局**：房主是唯一权威，负责校验每一步走法、判断将军 / 将死、维护悔棋求和，并把局面推给每个人（象棋没有暗牌，大家看到的是同一个视图）。
- **房号**：`xqcard-` + 4 位大写字母数字，对应 PeerJS 的 peer id；撞号会自动换一个。
- **座位**：0 号位（房主，红）→ 1 号位（对手，黑）→ 2 号位起是观战，最多 8 个连接。
- **掉线重连**：座位名字会保留，同名重新加入即可坐回原位（对局中也可以，回来立刻收到当前局面）。

## 常见问题

**连不上 / 一直转圈**
公共信令服务器偶尔抽风，等几秒重试；公司/校园网若禁用 UDP，P2P 可能打洞失败，换手机热点再试。
实在不行就[自建信令服务器](#进阶自建信令服务器)。

**提示「房号不存在或房主已离线」**
房号错了一位，或者房主关掉了页面。房主必须保持页面在前台（可以切后台，但别关）。

**问「房主是不是能看到我的棋」**
象棋本来就没有暗牌，双方看到的是同一个棋盘；房主只多做了一件事：替你校验走法是否合法。

**手机上打不开**
必须是 `https://` 或 `localhost`。GitHub Pages 天然是 https，没问题。

**第三个人为什么不能下棋**
房间只有两个对局位，第三位起自动进入观战（可以看到棋局和聊天）。想换人，让原来那位「菜单 → 离开房间」。

**想一个人练棋**
本版本只做真人对战，没有内置 AI；一个人可以开两个标签页自己跟自己下。

**我的卒过河了，为什么不能横走？**
先看它是不是被「牵住」了：如果它正好挡在两将（或挡住自己老将被车/炮将军）的直线上，
一横走就会让自己的将帅被将军 / 两将照面，这步棋按规则就是不成立的。点一下这个子，
会直接提示「这个子被牵住了：一动自己的将帅就会被将军（或将帅照面）」。
把将帅挪开、或者在中间补一手，它就能横走了。

## 进阶：自建信令服务器

`js/net.js` 支持覆盖 PeerJS 配置。在 `index.html` 里 `peerjs.min.js` 之前加一段：

```html
<script>
  // 默认留空 = 使用 PeerJS 官方公共服务器
  window.PEER_OPTIONS = {
    host: 'your-peer-server.com',
    port: 443,
    path: '/',
    secure: true,
    key: 'peerjs',
  };
</script>
```

自建方式：`npx peerjs --port 9000 --path /myapp`，再用 Nginx 反代到 https。

```
.
├── index.html              # 页面骨架（首页 / 房间 / 棋桌三个视图）

│   ├── net.js              # PeerJS 联机层（房主 HostRoom / 加入者 GuestRoom）
│   ├── ui.js               # 渲染与交互：棋盘、棋谱、聊天、结算浮层
│   ├── main.js             # 入口：大厅、房间、对局、网络串联
│   └── vendor/peerjs.min.js# PeerJS 1.5.5 浏览器版（已内置，不依赖 CDN）
├── test/
│   ├── rules.test.mjs      # 走子 / 将军 / 将死 / 记谱（纯逻辑，无依赖）
│   ├── game.test.mjs       # 走棋、悔棋、求和、认输、重开 + 5 局随机对局校验
│   ├── ui-smoke.mjs        # jsdom：点棋子走完整局，检查渲染与交互
│   └── e2e-smoke.mjs       # jsdom + 假 Peer：建房/入座/对弈/悔棋/聊天/观战/重连全流程
├── tools/serve.mjs         # 本地静态服务器
└── .github/workflows/pages.yml  # 推送 → 跑测试 → 部署 GitHub Pages
```

## 开发与测试

```bash
npm install        # 只有 UI / 端到端测试需要 jsdom，纯逻辑测试零依赖
npm run test       # 规则 + 状态机单元测试（含随机对局不变量校验）
npm run test:ui    # jsdom 里点棋子走完整局
npm run test:e2e   # jsdom + 假 PeerJS 跑完整联机流程
npm run test:all   # 上面三个一起跑（CI 跑的就是这个）
npm run serve      # 本地起服务，http://localhost:8080
```

`js/rules.js` 和 `js/game.js` 不碰 DOM、不碰网络，可以单独跑；
`js/ui.js` 只碰 DOM；`js/net.js` 只碰 PeerJS。想改规则改前两个文件即可。

CI：每次 push 到 `main` 会自动 `npm ci && npm run test:all`，测试通过才发布，所以改坏了不会上线。

> **改完记得升版本号**：GitHub Pages 的静态资源会被浏览器缓存 10 分钟。改了 `js/` 或 `css/` 后，
> 把 `index.html` 里两处 `?v=1`（`css/style.css?v=1`、`js/main.js?v=1`）的数字 +1，
> 子模块会自动继承这个版本号，朋友刷新即可看到新版。

`{t:'state', view}`、`{t:'chat', msg}`、`{t:'chatLog', list}`、`{t:'toast', msg}`、`{t:'full'}`

`{type:'draw'}` / `{type:'drawReply', accept}` / `{type:'resign'}` / `{type:'restart'}`

## 已知限制

- 只有标准双人对局，无 AI、无棋钟、无残局/复盘编辑。
- 长将、长捉、60 回合无吃子这类循环局面不做自动判罚，需要玩家自己约定或求和。
- 房主是权威、也是「服务器」，房主退出即散局。
- 依赖公共信令服务器，极端网络环境（对称 NAT）可能连不上。
- 棋谱只做展示，不支持「点某一手回到过去」的复盘。
